### OKX e modello
Verifica documentazione ufficiale della regione effettiva: https://my.okx.com/docs-v5/en/ e https://www.okx.com/en-eu/x-perps . Registra data, link, endpoint, rate limit, parametri, metadata e test in OKX_COMPATIBILITY. Non assumere che BTC-USDT-SWAP sia il prodotto del conto SEE: X-Perps è un contratto con scadenza; verifica FUTURES/ruleType e dati effettivi. Discovery pubblica e disponibilità sul conto sono verifiche diverse. Nessuna sostituzione LIVE silenziosa. Fee da conto se disponibili; altrimenti ipotesi configurata e dichiarata. Controlla stop/reduce-only/margine supportati dallo strumento.

Ollama locale: qwen3:1.7b iniziale, Q4_K_M da verificare con show/digest; num_ctx=2048, num_predict=256, una richiesta alla volta, thinking disabilitato se supportato, JSON Schema validato, timeout e coda bounded. GTX 1050 Ti 4 GB: misura GPU/RAM/latency, non garantire prestazioni. LLM legge testi dei collector; non cerca autonomamente e non può chiamare broker/shell. Nessun costo API senza consenso di budget.

### Limiti dell'autonomia
Il mandato copre sviluppo e integrazione software. Non copre trasferimenti, ordini reali, attivazione LIVE, acquisti, esposizione pubblica dei servizi, cancellazione dati operativi o formattazione dischi. LIVE rimane spento. I test Windows non accessibili vanno marcati NOT TESTED, non spacciati per PASS. Non è necessario attendere il collaudo Windows per integrare codice verificato in CI con limitazioni dichiarate, ma nessun gate dipendente dal server è considerato superato prima delle prove reali. Se controlli essenziali disponibili falliscono, correggi prima del merge.

## Specifica tecnica della release


**Ruolo.** Agisci come Staff Reliability Engineer, Exchange Integration Engineer, Application Security Engineer e Independent Trading Risk Auditor. Parti dalla release R2 esistente, ispeziona repository, architettura, test, documenti, event store e UI. Il mandato è rendere l'app distribuibile e **pronta alla valutazione** per trading LIVE, NON attivare LIVE né negoziare denaro reale durante il tuo lavoro. Nessun trasferimento reale, nessuna modifica permanente su account live e nessuna credenziale reale necessaria ai test. Conserva tutte le funzioni PAPER/intelligence e gli storici.

**A. OKX EEA adapter robusto.** Discovery strumenti X-Perps e restrizioni del conto via API SEE documentate; contract multiplier, tick/lot, min size, maintenance margin, session/service status, funding, settlement/rollover di prodotto X-Perps, fees reali tramite endpoint quando disponibile. Verifica se e come i derivati sono effettivamente abilitati sul conto; in assenza non fingere che lo siano. REST + private WS con auth segregata, signing corretto, rate limiting, request expiry, idempotent client order ID, retries safe (mai re-submit cieco su unknown status), reconcile open orders, fills, positions e margin. Cancel/reduce-only, reverse sequenziale, protective orders exchange-side e gestione failure dei protective orders. Test via mocks / OKX DEMO con soli keys demo e dichiarare eventuali API non supportate in demo.

**B. Paper / Demo / Live isolation.** Implementa runtime environment chiuso in configurazione firmata/loggata: `INTERNAL_PAPER`, `OKX_DEMO`, `OKX_LIVE`. Shared market/intelligence storico invariato; schemi ledger e PnL separati; LIVE equity = exchange assets/transactions, paper equity = paper ledger. Depositi/prelievi e cash flow non vengono confusi con PnL; account activity e fills reconciled. Attivazione LIVE esclusivamente tramite: (1) check compatibilità OS aggiornato; (2) credenziali LIVE caricate solo sul PC tramite secret store; (3) KYC/appropriateness OKX done; (4) dry-run / read-only; (5) verify zero pending unsafe order; (6) explicit user confirmation + confirmation phrase + cooldown opzionale; (7) audit immutable event; (8) configurable lower initial exposure max than 5x in live while hard cap remains 5x; (9) startup state reconciliation. Niente automatic copy paper position -> live, niente deploy auto con API reali. Se switch da LIVE a PAPER, blocca nuove azioni LIVE; posizioni LIVE eventualmente presenti devono restare monitorate e il passaggio è impedito fino a piano di gestione esplicito. Mai nascondere posizioni aperte dietro modalità PAPER.

**C. Security hardening.** API credentials `Read/Trade`, **mai Withdraw**; IP whitelisting se praticabile e home IP stabile; secret storage tramite Windows DPAPI/Credential Manager o meccanismo locale cifrato con ACL, non `.env` in repo. Dashboard localhost-only, login Windows protetto, nessuna pubblicazione porta in Internet, CSP e validazione UI/API, CSRF per comandi sensibili se applicabile, RBAC locale semplice, no prompt injection eseguibile. LLM no accesso shell/broker; rate-limit e spend limit X API. Logs redatti automatico per tokens/headers. GitHub CI solo fixtures, PR reviews, dependency scan e secret scan; no runner sul server con API keys, no accesso remoto aperto al pubblico, build release firmata/hash verificato e rollout manuale con rollback.

**D. Windows startup/recovery.** `install_windows_tasks.ps1`, `uninstall_windows_tasks.ps1`, `start.ps1`, `stop.ps1`, `status.ps1`, `doctor.ps1`, `backup.ps1`, `restore_dry_run.ps1`, `export_diagnostics.ps1` con precheck e no destructive defaults. Avvio automatico a boot tramite Task Scheduler con privilegi minimi e account appropriato, session-independent; health watchdog indipendente da Ollama. Gestione Windows Update/reboot, sqlite? NO PostgreSQL only for durable ledger, wait for database healthy, verify DB migrations, exchange reconciliation before trade, queued events once, audit. Task che perde DB o API privata = no new orders. Keep paper/live idle exposure cash. PostgreSQL su HDD mirror, retention/partitions, vacuum e backups con restore test periodico; state transitions DB transaction; spostare archive compressi via job, backup offline distinto da mirror. Metriche CPU/RAM/VRAM/disk IO e soglie per throttling LLM. File `.env.example` senza segreti; non richiedere Docker.

**E. Risk & independent verification.** Hard max exposure +5/-5 times equity (not just margin setting), configurable lower max default, isolated margin when supported, account currency and contract specs verified, budget risk per trade (planned 0.25-0.5% equity); max daily/weekly loss and DD stops, liquidation buffer, quote freshness, order protection, fee/funding/slippage estimated cost, flapping filter, min edge, position size rounding. Exchange-side stop order creation and verification, partial fill and race test, abnormal volatility emergency, stale/unknown state hold. Non eseguire force close in condizioni di prezzo ignoto come risposta predefinita. Test incognito `kill switch`, stale price, OS sleep, network failure, database loss, LLM queue overload, high spread, WS disconnect, duplicate/reordered messages, API 429/5xx, protective order reject, leveraged reversal while account short of margin, exchange downtime, X-Perps expiry/settlement rollover e balance changes. Correggi finché R1/R2 tests regressions remain green.

**F. Calibrated model & go-live evaluation report.** Non attivare LIVE sulla base di successo casuale. Prepara report di forward testing su dati live con periodi di high/low volatility e US/Asia/EU/weekend; net returns including fees/funding, max DD, independent sample size, risk-adjusted metrics, uncertainty/confidence calibration, comparison with simpler baseline, and test of operational incidents. Definisci GO/NO-GO evidence gates ma NON auto-approvare; live-enable flag deve rimanere false nel repository. Se non esistono osservazioni sufficienti, report `NOT READY - insufficient forward sample` e continua PAPER. Nessun rendimento garantito; rischio di perdite > stop in eventi estremi.

**G. Professionale final UI.** In dashboard aggiungi `Release/Environment/Health` header, confirmation modal esplicita per LIVE, hard risk controls, emergency suspension, accounts segregati, analytics storico paper vs live con loro cash flows, full audit timeline per decisioni e API calls, log filtrabili, model version, last market timestamp, provider quotas/budget, hardware health, backup status e build version. Performance adatta al monitor 1080p via Chrome Remote Desktop. Crea screenshot in test quando tecnicamente possibile e confrontali con design system.

**Consegna.** Scrivi codice reale, integrazioni, script Windows, test, ci/check, changelog, migration, secure configuration guide, manuale operazioni e playbook incident. Genera `docs/LIVE_READINESS.md` come checklist con stato PASS/FAIL/NOT TESTED per ogni controllo e no fake passing. PR integrata automaticamente + tag `v1.0.0-live-capable` solo se le verifiche in ambiente autorizzato passano; senza prova non attribuire quel tag, usare `v0.3.0-live-gated`. Non testare ordini LIVE senza consenso. Mostra comandi e verifiche finali sul server, riepilogo delle limitazioni, ed esatta procedura di rollback. Lascia LIVE spento: l'approvazione e l'abilitazione sono un'azione separata dell'utente dopo GO.
