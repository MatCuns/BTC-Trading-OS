Nessun costo API senza consenso di budget.

**Target architetturale R1.**
(1) `shared market feed`: connettore pubblico OKX Europe REST/WebSocket per prezzo, trade aggregati, bid/ask e (opzionale iniziale) depth; discovery dinamica dello strumento BTC X-Perps effettivamente visibile sul canale SEE, validazione precision/lot size/margin, fallback se lo strumento non è disponibile, time sync, heartbeat, reconnect/backoff/jitter, rate limits, staleness e indicatori feed health. NON sostituire l'instrument discovery con `BTC-USDT-SWAP` hardcoded; se X-Perps non è negoziabile in demo, fornire motivazione precisa e mantenere PAPER interno.
(2) `database`: PostgreSQL locale. Schema `market`, `system`, `paper`, `live` con migrazioni Alembic; `event` timestamp UTC, ingest time, source, payload reference, quality, dedupe hash. Paper e live hanno tabelle/ledger separati (account, orders, fills, positions, balances, snapshots, funding, realized/unrealized PnL), e `environment_id` in ogni DTO; il LIVE schema esiste ma è non utilizzabile senza autorizzazione. Progetta transazioni, chiavi unique, indici, retention e archiviazione bulk. Non utilizzare SQLite come sostituto silenzioso in produzione. Per smoke-test offline è lecito mock/test DB. Implementa backup script e restore check non distruttivi.
(3) `broker layer`: interfaccia tipizzata `BrokerAdapter` con `InternalPaperBroker`, `OkxDemoAdapter` (API demo read/trade con credenziali demo opzionali) e `OkxLiveAdapter` soltanto stub disabilitato in R1. L'InternalPaperBroker usa prezzi/spread reali come input, calcola fee maker/taker, slippage simulato configurabile, funding se disponibile, ordine partial fill, stop e trigger; segnala chiaramente limitazioni di realismo. `OkxDemoAdapter` usa endpoint SEE demo e `x-simulated-trading: 1`, ma l'ambiente demo serve a testare integrazione, NON come benchmark di rendimento di mercato. Chiavi e passphrase esistono solo sul server in secure secrets local; nessuna nel repo.
(4) `trading state machine`: posizione target continua in [-5,+5] come *maximum technical exposure*, ma default conservativo <=1x per il paper. Azioni FLAT / OPEN LONG / OPEN SHORT / HOLD / REDUCE / REVERSE. Nessuna entry automatica basata su regole farlocche: per R1 implementa una `ReferenceStrategy` deterministic semplice, disabilitata per default fino all'opt-in PAPER, con logiche trasparenti di trend/volatility e fallback FLAT. Supporta posizione zero, equity, exchange round lot e minNotional. `reverse` implementato come close reduce-only, acknowledge fills, reconcile, then open other side; ordini con client IDs idempotenti, reconciliation before retry, gestione partial fills e order unknown.
(5) `risk`: motore separato dalla strategia con cap nozionale hard 5x, budget di perdita per trade parametrico (default 0,5% equity come limite pianificato), stop server/exchange-side simulati nel paper, max daily loss, max drawdown, stale feed block, isolated margin preference quando disponibile, kill switch controllabile in UI, costo minimo previsto, margine disponibile e blocco di nuovi ordini se persistenza/risk status/posizioni ignoti. Le perdite reali possono oltrepassare gli stop, non dichiarare garanzie. Quando feed manca, fermare nuove aperture senza chiudere a mercato ciecamente.
(6) `observability`: JSON structured logs con run_id, decision_id, environment, timestamps, source, severity e correlation IDs; rotazione log; notifiche locali/UI; heartbeat processi, uptime, queue lag, reconnect e exception counts. Startup reconciliation, Windows Task Scheduler bootstrap `start.ps1`, `stop.ps1`, `health.ps1`, `doctor.ps1` e `install_tasks.ps1` con controllo privilegi, servizi gestiti e rollback. I test non devono creare task permanenti né formattare volumi. Usa health endpoints.
(7) `frontend`: crea React + TypeScript dark professional finance UI responsiva desktop con nav Overview, Markets, Positions, Orders, Analytics, System, Settings; barra STATUS PAPER/DEMO e disabilitazione LIVE visibile; connessione dati push via WebSocket interno/SSE, nessun refresh continuo completo, grafico BTC con prezzo live, equity paper, saldo, leverages, risk flags, decision timeline, logs e feed freshness. Configurable chart time range e filtri; design sobrio tipo terminal Bloomberg/quant, tipografia coerente, no placeholders inventati sui KPI. Componenti accessibili e stati loading/error/empty. UI leggibile 1920x1080 su Chrome Remote Desktop. Crea release bundle frontend compilato e servibile da FastAPI senza node server persistente in produzione.
(8) `CI + quality`: GitHub-hosted runner ubuntu/windows se possibile con lint/format (ruff), mypy o pyright, pytest async/integration e frontend typecheck/test/build; nessun segreto live in CI. Fixture e mock di websocket, DB test separato; CI branch protection consigliata. Non installare runner self-hosted sul server con chiavi.
